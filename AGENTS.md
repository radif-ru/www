# AGENTS.md

Правила работы над репозиторием `radif-ru/www` — исходным кодом сайта-резюме
[radif.ru](https://radif.ru). Единая точка входа и источник истины для всех
AI-агентов проекта (Cursor, Windsurf, Devin, Claude Code, GitHub Copilot,
JetBrains AI). Меняй правила **здесь**.

> **Соразмерность.** Это статический сайт на ~1,5 тыс. строк, а не платформа.
> Здесь сознательно нет 11 скиллов-дисциплин и досок со спринтами, как в
> [`ai-multi-agent-system`](https://github.com/radif-ru/ai-multi-agent-system) —
> процесс должен быть по размеру задачи. Автоматизировано ровно то, что
> действительно ломается: факты, ссылки и синхронность мета-данных.

## 1. Главное правило: резюме — это документ о фактах

Каждое утверждение на сайте должно быть проверяемым. Это не стилистическое
пожелание, а требование к продукту: одна недостоверная цифра обесценивает
весь документ.

- **Цифру — только со ссылкой на источник.** Число тестов, покрытие, количество
  спринтов, инструментов, таблиц, эндпоинтов берутся из прогона или из кода, а
  не из памяти. Изменилось в источнике — правь здесь.
- **Не округляй в свою пользу.** `889 тестов` лучше, чем `900+`. Если точное
  число неизвестно — ставь порядковую величину с `~` и говори об этом прямо.
- **Не выдумывай достижений.** Нет права дописывать «оптимизировал в 10 раз»,
  если этого не сказал автор. Сомневаешься в формулировке — спроси.
- **Рабочий код под NDA.** Про коммерческие проекты можно писать стек, процессы
  и агрегированный масштаб (порядок числа таблиц, эндпоинтов, строк). Нельзя:
  фрагменты кода, имена таблиц и полей, внутренние ссылки на приватные
  репозитории и GitLab, данные клиентов.
- **Не ссылайся на приватные репозитории** как на публичные. Их помечают текстом
  «приватный», а не ссылкой.
- **Запрещённая лексика:** «уникальный», «инновационный», «не имеющий
  аналогов», «эксперт мирового уровня». Экспертность показывают факты и
  инженерные детали, а не прилагательные.

### Только относительные пути

В коммиты, документацию и код **никогда** не попадают пути, работающие только
на машине автора: домашний каталог, смонтированные диски Windows в WSL,
UNC-пути к WSL, ссылки на локальный файл, абсолютный путь к самому
репозиторию. Такой путь бесполезен любому другому читателю и выдаёт черновик
вместо документа. Внутри репозитория — только относительные пути
(`./scripts/preflight.sh`, `../AGENTS.md`), для внешних ресурсов — URL.

Точные шаблоны запрещённых путей держит `scripts/check_agents_sync.py`, там же
лежат и примеры. Здесь их нет намеренно: документ правила не должен нарушать
правило, которое описывает, — иначе гейт ловит собственную документацию, а
единственный способ его пройти — ослабить проверку.

Это касается и эталонного проекта: на него ссылаемся **только** как на
<https://github.com/radif-ru/ai-multi-agent-system>, никогда — локальным путём.

Исключение — пути внутри контейнеров (например `/home/app/...` в
`docker-compose.prod.yml` и конфигурации nginx): они абсолютные по своей
природе и одинаковы у всех. Критерий простой: «сломается ли это у другого
человека». Проверяет `scripts/check_agents_sync.py`.

## 2. Автоматизируй без ИИ

Детерминированное и повторяемое — скриптом или CI-гейтом, а не глазами и не ИИ.

| Гейт                                   | Что проверяет                                                                                                                                                                           |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `npm run lint`                         | Stylelint (CSS), ESLint (JS), html-validate (HTML)                                                                                                                                      |
| `npm run format:check`                 | Prettier по конфигам и докам                                                                                                                                                            |
| `python3 scripts/check_meta_sync.py`   | Совпадение `<title>` / `og:title` / `twitter:title` / JSON-LD `name`; `dateModified` == `<lastmod>`; валидность JSON-LD; битые внутренние якоря; `target="_blank"` без `rel="noopener"` |
| `python3 scripts/check_agents_sync.py` | Зеркала правил и скиллов — symlink'и, а не копии; YAML-заголовки скиллов; скиллы упомянуты в `AGENTS.md`; в репозитории нет путей, работающих только на машине автора                   |
| `python3 scripts/check_links.py`       | Живы ли внешние ссылки (ходит в сеть)                                                                                                                                                   |
| `./scripts/preflight.sh`               | Всё перечисленное выше одной командой                                                                                                                                                   |

Правило: перед коммитом — `./scripts/preflight.sh`. Красный гейт чинят, а не
маскируют. Появилась третья ручная сверка — пиши скрипт, а не проверяй в
четвёртый раз.

`check_links.py` ходит в сеть, поэтому **не** блокирует CI на каждый push:
внешние сервисы отдают 429 и 5xx по своим причинам. Он запускается локально
перед публикацией и по расписанию отдельным workflow.

Он же отделяет дефект от качества связи: поломка — это код ответа 4xx/5xx или
ссылка на исчезнувший файл репозитория, а обрыв соединения и таймаут идут в
предупреждения и гейт не роняют. Иначе красный цвет означал бы «плохой Wi-Fi»,
и на него перестали бы смотреть. Предупреждения читает человек — они печатаются
списком.

## 3. Хендмейд-файлы не форматируем

`index.html`, `assets/style.css`, `assets/app.js` отформатированы вручную
(компактно, по смысловым блокам) и лежат в `.prettierignore`. Prettier их не
трогает — и агент тоже не «причёсывает». Стиль соседнего кода сохраняем даже
если написали бы иначе.

Обратная сторона: `README.md` и конфиги Prettier форматирует. После правок
markdown-таблиц запускай `npm run format` и **перечитывай файл** — Prettier
переставляет выравнивание ячеек и может «съесть» правку, сделанную по старому
выравниванию.

## 4. Бейджи

- Каждый URL бейджа проверяем `curl` до коммита: и код ответа, и что логотип
  реально отрисовался. shields.io при неизвестном `logo=` молча отдаёт бейдж
  **без** логотипа — визуально это брак, а не ошибка.
- Проверка логотипа: в ответе должен быть `image/svg+xml;base64`.

  ```bash
  curl -s "https://img.shields.io/badge/test-x-blue?logo=NAME" | grep -q 'image/svg+xml;base64' \
    && echo OK || echo "нет логотипа"
  ```

- Имена логотипов — из [simple-icons](https://simpleicons.org/). Осторожно с
  переименованиями: работает `logo=css`, а `logo=css3` — уже нет.
- Статические бейджи фиксируют текущие значения гейтов. Меняется значение —
  меняется бейдж в том же коммите.

## 5. Дата модификации

При содержательной правке сайта обновляй **обе** даты одним значением:
`dateModified` в JSON-LD (`index.html`) и `<lastmod>` в `sitemap.xml`.
Расхождение поймает `check_meta_sync.py`.

## 6. Деплой

Прод в `docker-compose.prod.yml` монтирует конкретные файлы и папки в
`/var/www`. Добавил новый внешний ассет — примонтируй его и **пересоздай**
контейнер (`docker compose -f docker-compose.prod.yml up -d`), а не reload.
Деплой выполняет автор, не агент.

## 7. Поведение агента

- **Сначала думай, потом кодь.** Возможны разные трактовки задачи — назови их,
  не выбирай молча. Непонятно — остановись и спроси.
- **Хирургические правки.** Трогай только то, что нужно для задачи. Не рефактори
  работающее, не «улучшай» соседние формулировки заодно.
- **Минимализм.** Никаких абстракций ради одного использования и никакого
  процесса ради процесса — см. врезку про соразмерность выше.
- **Не пушить и не деплоить.** Агент работает локально; `git push`, деплой и
  публикация — за автором.

## 8. Скиллы

Скиллы-дисциплины живут в `.agents/skills/<name>/SKILL.md`. Если тема задачи
совпадает со скиллом — прочитай его **до** правок.

| Скилл                                                                                                      | Когда читать                                              |
| ---------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| [`.agents/skills/resume-content-discipline/SKILL.md`](./.agents/skills/resume-content-discipline/SKILL.md) | Любая правка текста резюме: цифры, формулировки, NDA, тон |
| [`.agents/skills/badge-discipline/SKILL.md`](./.agents/skills/badge-discipline/SKILL.md)                   | Добавление или изменение бейджей в README                 |

## 9. Зеркала для других агентов

Этот файл — единственный источник истины. Все остальные точки входа —
**symlink'и** на него, а не копии: копия расходится с источником на первой же
правке, и агенты начинают работать по разным правилам.

| Зеркало                           | Тип     | Цель                          |
| --------------------------------- | ------- | ----------------------------- |
| `CLAUDE.md`                       | symlink | `AGENTS.md`                   |
| `GEMINI.md`                       | symlink | `AGENTS.md`                   |
| `QWEN.md`                         | symlink | `AGENTS.md`                   |
| `.github/copilot-instructions.md` | symlink | `../AGENTS.md`                |
| `.devin/rules/agents.md`          | ссылка  | этот файл                     |
| `.cursor/rules/agents.mdc`        | ссылка  | этот файл                     |
| `.claude/skills/<name>`           | symlink | `../../.agents/skills/<name>` |

Добавил скилл в `.agents/skills/` — сразу заведи зеркало и упомяни его в §8:

```bash
ln -sfn ../../.agents/skills/<name> .claude/skills/<name>
python3 scripts/check_agents_sync.py
```

Новому агенту нужен свой файл правил — добавляй symlink (или короткую ссылку,
если формат агента требует собственный синтаксис, как у Cursor), обнови таблицу
выше и `MIRRORS` в `scripts/check_agents_sync.py`. Целостность зеркал —
гейт в CI, а не ручная сверка.
